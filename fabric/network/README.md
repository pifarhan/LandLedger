# Real Hyperledger Fabric integration

This project now includes a Fabric Gateway adapter and deployment scripts.

## 1. Prerequisites

- Docker Desktop / Docker Engine
- Node.js 20+
- Git
- Hyperledger Fabric 2.5+ test-network (the bootstrap script downloads fabric-samples)

## 2. Deploy

From the project root:

```bash
./fabric/network/bootstrap.sh
```

The script creates `landchannel` and deploys the Go `landrecords` chaincode.

## 3. Configure API

Copy `.env.example` to `server/.env`, set the Fabric certificate/key/TLS paths generated by the Fabric test network, then set:

```env
FABRIC_MODE=fabric
FABRIC_CHANNEL=landchannel
FABRIC_CHAINCODE=landrecords
FABRIC_MSP_ID=Org1MSP
FABRIC_PEER_ENDPOINT=localhost:7051
FABRIC_TLS_SERVER_NAME=peer0.org1.example.com
```

The API maps these application ledger events to real Fabric transactions:

- PROPERTY_REGISTERED -> CreateProperty
- PROPERTY_APPROVED -> ApproveProperty
- TRANSFER_PROPOSED -> ProposeTransfer
- TRANSFER_ACCEPTED -> AcceptTransfer
- TRANSFER_FINALIZED -> FinalizeTransfer

Documents and owner/parcel personal attributes remain off-chain. The channel stores only:

- SHA-256 digest of a captured source document and source reference;
- HMAC-SHA-256 references for parcel key, claimant, title/address and storage key;
- non-personal administrative metadata and workflow state.

`FABRIC_REFERENCE_HMAC_SECRET` is generated by bootstrap and written into `server/.env.fabric` with restrictive file permissions. Back it up securely and keep it stable across deployments; rotating it requires a planned reference migration. Do not store this secret in Git or a shared project ZIP. If an authorised production service uses multiple application replicas, all replicas must read the same secret from a managed secret store.

## 4. Verify

After login as an authority, call `GET /api/fabric/status`. The API should report `connected: true`.

Then exercise the normal registration/approval/transfer workflow. In Fabric mode, the ledger event is submitted to the deployed chaincode instead of the local append-only ledger.

## Important research boundary

The bootstrap script uses the Fabric Samples **test-network** and is a development integration proof only. It is not a production topology. A production deployment requires a stateful multi-node Raft ordering service, organisation-owned CAs/MSPs, TLS certificate lifecycle, HSM/KMS-backed keys, private-data collection policies, independent peer organisations, backups/restore drills, monitoring, operational SLOs, disaster recovery, change-control and legal approval from participating authorities. This workspace has not deployed or benchmarked such a production network.

The Fabric ledger does not confer legal title and is not connected to a government land registry. A successful application workflow or chaincode transaction is not statutory mutation. Public-channel state intentionally excludes raw claimant names, parcel identifiers, addresses and title text; use only keyed references and off-chain source evidence under role-based access controls.
